# 热词纠错策略

确定性、立刻可做的只有两类：用户写出的 `错词→正词`，以及英文热词的大小写、空格和 `._-` 归一。`CodeX`、`open claw` 可以收成词表里的写法。显式英文别名紧贴汉字时仍应生效（`clawd的CLI`→`Claude的CLI`）；只有紧贴另一个 ASCII 单词字符时才视作更长英文标识的一部分。

短中文不能只靠无声调拼音替换。`时期`、`十七`、`湿气` 的无声调拼音都是 `shi qi`，其中 `时期` 和 `十七` 的声调也相同。词频只决定候选送给判断器时的顺序，不能当成改对了的证据。

数字、URL、邮箱、反引号和蛇形代码，以及紧跟在「不 / 没 / 别 / 不是 / 不要 / 没有」等否定后面的那个词，不参与替换，也不送去判断。

SemIf 只在调用方给出的有限候选里选择，候选里始终有保留原文。下面任一情况都保留原文：未知标签、没有概率、空概率、NaN、Infinity、概率和不为 1、choice 不是唯一最高项、网络失败或超时，以及弱分布。弱分布的固定门槛是最高项至少 0.70，并且比第二名至少高出 0.20。因此 0.51 对 0.49、0.60 对 0.40 都保留原文；0.90 对 0.10 才过这道门。这是保守拒绝规则，不是测出来的准确率。

`StreamingHotwordCorrector` 默认 `enabled=False`，端点为空也不联网，这时不启动后台线程。词表最多保留 64 项，显式别名优先，所以写在末尾的 `错词→正词` 仍然生效。单次判断最多 8 个选项，其中包含保留原文，不是把整个词表截成 8 条。一次快照只判断一个跨度。`submit` 对同一原始文本幂等。中间夹了另一句之后，只要这句的结果还在最多 32 条缓存里，再次 `submit` 也不再请求。`cancel` 会清空这份缓存。`finish` 可以接收从未 `submit` 的最终句，并只等待一个 `timeout_s`。后台最多一个在途请求加一个最新请求。`cancel` 作废当前结果；`close` 不等待 200ms。

`correction` extra 由打包配置声明，包含 `requests` 和 `pypinyin`。本模块不在默认关闭或端点为空时导入 `requests`。打开端点但没装 `requests` 时，`submit` / `finish` 抛出 `ImportError`，不会假装没连上。没装 `pypinyin` 时，显式别名和英文归一仍可用；同音候选不会生成，因此这些跨度不会发给 SemIf，这不是网络失败。

自动词库按条数上限删除低确认词时，同一事务会删掉对应的来源行，不留下孤儿记录，也不为了清理而清空仍在上限内的词。

旧服务的检查记录：`GET /health` 曾报告 `semif-direct-options-v1` 和 `semif-qwen35-4b`。2026-09-29，111 服务器的当前接口 `http://192.168.5.111:42171/v1/systemone` 报告 `plumb-direct-options-v1`、`plumb-4b-v5-q8`（`crh225/plumb-4b-GGUF Q8_0`）；实际 POST 仍接受 `state` + `questions.pick.criteria` 并返回同形的候选概率。模型由服务器管理，以实时健康检查为准。当前本机打开了上下文纠词；普通安装仍默认关闭。Plumb 的几句连通性和语境试例只验证接入，不代表完整准确率，旧 SemIf 的质量数据也不能直接外推给它。

同一组 12 句里，裸词 criteria（`keep=试气` 这种）应改 5 句修对 0，应留 7 句误改 0。改成判定句加完整候选句后，修对 2（登陆页→登录，在坐的各位→在座），误改仍是 0。两句「试气」仍然留错；「你必需今天交报告」虽然选了替换，概率只有约 0.53，门槛拒绝。因此 `_judge` 采用这种完整候选句，但替换仍只发生在原跨度，不按流畅性删字。2/5 不能当生产质量，默认继续关闭，门槛也不下调。

`trim_new_piece` 不再删最后一个字，也不再访问网络。

纠词来源是 `correction_provider`：`semif`（默认，兼容旧配置）或 `jev`。SemIf 仍要端点和不超过 0.35 秒的超时。官方 Jev 不把密钥放进 Recordian 配置，走本机 `jev ask`（子进程里 `SEMIF=0`、`TYPESAFE_MODEL=jev-latest`，正文只走 stdin）。Jev 的整句预算默认 1.5 秒、上限 2 秒；没启用或没有别名时不启动 CLI。门槛仍是 0.70/0.20。超时、坏回复和不确定都保留原文。

语境别名（`contextual_aliases`，如 `{'heard':'jeff','word':'jev','meaning':'软件工具'}`）不做无条件替换。只有未保护、非元话语（前后 4 字内没有「而是/改成/写成/说成/叫作/叫做」）、且在整句里只出现一次的 heard 词，才在当前句或上一段里出现安装、启动、运行、程序、工具、测试、项目这类软件语境时，发给当前纠词来源（内网 SemIf 或官方 Jev）做语义角色判断。词表里的含义本身不是软件语境；没有这类证据就不提问、不替换。提问时候选固定为「这里指的是软件工具、程序或插件。/ 这里指的是一个人。/ 不清楚，或者以上都不是。」，说明里如实写出「用户的常用词里，jev 是这个用户的软件工具；语音识别经常把它误写成 jeff」。只有角色判为 tool 且过 0.70/0.20 门槛才替换原跨度，拼写用用户声明的 word。一句话里同一个 heard 出现多次时完全不判断：实测共现句会把指人的那次也拖向 tool（0.76–0.98 过门槛），全或无问法则全部弃权。一个快照最多顺序发 1 个拼音 pick 加 3 个角色请求，每请求一问；把多个跨度塞进一个请求实测会降低单跨度准确率。构造器接受 `context`（上一段尾部，最多留 256 字），只作为判断输入写进 state，绝不返回、编辑或提交；缓存按 generation+context 双重绑定，过期结果不应用。

口播数字与 URL 归一（`spoken_formatting.py`）是纯函数、幂等、无需配置，在 `_normalize_final_text` 里对实时和一次性定稿都生效。普通中文句子里的数量和序数保持中文（我有二十五个文件、三个苹果、等待十秒、第十二个）；模型已输出短阿拉伯数量时也转回中文（我有25个文件→我有二十五个文件、2个→两个）。孤立数词仍可转为阿拉伯数字（二十五→25、一百零二→102），一万二、两三天、三四个等近似读法不猜。明确的号码标记整段转换（编号零零一二→0012，保留前导零）；完整且以 `1[3-9]` 开头的 11 位中文数位串，即使夹在中文里、没有手机号标记，也按手机号转换。小数（三点一四→3.14）、百分比（百分之三十五→35%）、四段 IPv4（一九二点一六八点五点一一一→192.168.5.111，段值 0–255）、年月日结构（二〇二六年九月二十四日→2026年9月24日，保留中文分隔）、钟点及强 URL 结构继续格式化。代码、邮箱、现成的号码、日期和完整网址保持原样。`_normalize_final_text` 的去重不会折叠纯数字重复段；重复调用格式器结果不变。

自动词库里，只有 `source='user_confirmed'` 是用户确认。`asr`、`refined`、`corrected` 只增加见到次数。不带 `source` 的旧调用仍会增加 `accept_count`，这是兼容行为，来源记为 `legacy`，不是 `user_confirmed`。打开旧数据库只补列，不删除已有词。
