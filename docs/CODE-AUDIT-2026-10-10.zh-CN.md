# Recordian 代码与安全审核

审核基线：`2c590a2bce69334616d196574379d6fb14767c14`。跟踪事项：`Recordian-95`。
范围包括录音、连续听写、Fcitx 输入、精炼提供者、设置保存、Agent 进程、网络服务、私有文件、Rust/C++ 接口和依赖。
主目录用户已有修改保留在原位置；审核在独立工作目录完成。

## 方法与约束

按相互独立的功能边界审查，先复现再修复，以失败回归和修复后通过作为证据。
网络加固及非网络修改分别接受额外审查。只删除经过全仓引用检查、没有入口或兼容性用途的私有旧代码。
保留 160 ms 调度、关闭思考、25 秒回退保护、连续分段、焦点失效保护和禁止重试不确定输入的约束。
测试中的本机 socket、D-Bus、GTK/Fcitx 使用隔离环境；不向用户正在操作的窗口注入测试内容。

## 修复结果

| 问题 | 触发与后果 | 处理 |
| --- | --- | --- |
| 取消与最终输入的竞态 | 预编辑等待期间取消，旧 worker 仍可能提交 | 在最终写入边界重新检查取消 |
| 忙时再次启动改变目标 | 第二次开始被拒绝，但已把第一个任务目标改成新窗口 | 取得任务所有权后再改变目标和 committer |
| 中断精炼被当完整正文 | 流式模型已输出一部分随后超时，丢失原文后半段 | 未完整结束时保留 ASR 原文，避免重复已经提交的文字 |
| 已识别文本被整体静音判断丢弃 | 短语音后长静音降低整段 RMS | 有预取转写结果时不再用整段静音检测覆盖它 |
| 长录音停止时内存增长 | 静音检测一次读完整 WAV，即使转写已经完成 | 必需检测时分块累计，不扫描已经完成的预取路径 |
| 输入法过期残留 | 删除过期 token 后失去清理自己预编辑的机会 | 检查新会话前清理仍能证明自有的残留 |
| 输入法回显较慢导致尾段失效 | 下一段覆盖上一段尚未确认的回显 | 有界保存自身累计提交快照，允许逐段或合并确认；外部编辑仍使会话失效 |
| llama.cpp 丢段落与假超时 | 首空行截断；执行器退出仍等待模型 | 保留正文段落；等待到期返回，原生任务仅允许一个在途 |
| 云精炼截断结果及流式思考泄露 | 接受 length/提前 EOF；think 标签跨块未过滤 | 检查完成状态，统一跨块过滤，保留关闭思考请求参数 |
| Qwen 与 HTTP ASR 的完成和标签解析 | Qwen 达到生成上限而无 EOS；think/asr_text 跨块；短裸文本或 language 开头正文 | 检查 EOS/完成状态，保持解析状态，拒绝不完整协议，保留合法完整正文 |
| 设置与声纹参数无效 | 浮点形式整数验证通过却保存失败；声纹阈值参数被忽略 | 统一整数解析，实际应用调用者给定的质量阈值 |
| 后端误杀 | 根据全系统进程命令子串把其他实例当孤儿 | 删除无法证明所有权的扫描，只管理自己持有的子进程 |
| 无鉴权跨网粘贴与旧 ASR 默认暴露 | 局域网任意可达设备注入文字或消耗模型 | 默认回环；直接跨网要求令牌与 TLS；部署脚本不再打开所有网卡 |
| 消息、等待和上传缺乏边界 | 换行绕过大小限制、慢连接长期占位、无限等待或音频扩张 | 总截止时间、连接/推理槽位、长度及解码样本/时长预算 |
| 私有文件与日志 | 固定临时文件名可跟随符号链接；日志保留剪贴板正文 | 随机私有临时文件原子替换；令牌文件检查；默认正文日志只记录长度，日志文件私有且不跟随符号链接；重新配置关闭旧句柄 |

已删除 `_stream_display_delta`、`_StreamingCommitAccumulator`、`_append_only_delta` 和上述无归属证据的进程清理实现。
保留公开 CLI、兼容 shim、替代 provider 和生命周期必要参数；静态工具的“未使用”提示不能单独证明这些可删。
修正 Qwen context 截断注释、llama.cpp 超时语义、HTTP 默认绑定、原型脚本中的用户专属 token 路径及 WebSocket SHA1 校验用途注释。
安全网络配置和各接口的具体预算见 [安全部署说明](SECURE-NETWORK.zh-CN.md)。

## 依赖扫描与未完成边界

本机桌面 Python 环境的 Werkzeug 从 3.1.8 升至 3.1.9，并在依赖声明及锁文件中设置最低安全版本。
模型 Python 环境也安装了相同兼容补丁。该通告涉及 Windows/NTFS 特殊文件名：
[上游 GHSA-g6x2-hccm-hh4m](https://github.com/pallets/werkzeug/security/advisories/GHSA-g6x2-hccm-hh4m)，不能据此声称本机 Linux 已被利用。
桌面环境复扫未发现可由扫描数据库识别的已公布漏洞；本项目源码由本次代码审查覆盖。

模型环境复扫仍有 **86 条依赖安全通告记录，涉及 6 个包**：

| 已安装包 | 版本 | 通告记录数 |
| --- | --- | --- |
| accelerate | 1.12.0 | 1 |
| diskcache | 5.6.3 | 2 |
| torch | 2.9.1 | 4 |
| transformers | 4.57.6 | 9 |
| vllm | 0.14.0 | 68 |
| xgrammar | 0.1.29 | 2 |

这是已安装依赖的数据库匹配，不等于 86 个漏洞都可通过 Recordian 利用。
当前实机识别服务确认使用 `llama-native` 后端和 `127.0.0.1:8321`，并不是 vLLM HTTP 服务；
模型处理器等依赖仍需逐条核对实际可达路径，不能把未用到某个服务器入口解释为整包无风险。
`Recordian-96` 跟踪模型依赖的隔离升级、兼容性、识别一致性、延迟和可恢复部署验证。
不在本次审核中贸然升级到另一代 GPU 框架，也不把依赖风险标为已解决。

已配置的局域网精炼/Jev 服务仍使用 HTTP；本次加固的 Recordian 自有网络服务没有改变这些外部模型端点。
局域网并不等于传输加密，相关服务的 TLS 或可信隧道迁移由 `Recordian-97` 跟踪，需保留关闭思考并验证实际模型调用。

llama.cpp 的 Python 等待现在有界，但无法强制结束卡住的原生线程；该实例保留最多一个在途任务并拒绝继续累积。
没有归属证据的真正遗留进程也不再自动回收，应由其所属服务或有证据的维护流程处理。

## 验证证据

最终全量：`RECORDIAN_NATIVE_CORE=required` **1588 passed、41 skipped、0 failed**（58.94 秒）；
`RECORDIAN_NATIVE_CORE=python` **1588 passed、41 skipped、0 failed**（60.02 秒）。
两个模式均有 1 条外部 PyGI 弃用提醒。跳过项目包含需要可选模型、外部环境或显式开启的集成检查；不将跳过算作通过。
全仓源码与测试 Ruff 检查、依赖锁一致性、差异格式检查通过，最终源码构建出 sdist 和包含 ABI1 原生库的 Linux wheel。
网络专项使用真实回环 socket/TLS 与假模型验证慢连接保护，输入法专项包含 24 个生产 C++ 类的隔离合成用例。
审核交付的是代码；常驻桌面、输入法和识别服务未在本次审核中重启，因此不能把合并代码等同于全部运行进程已加载修复。
实际自然麦克风长时间使用与日常应用观察仍由 `Recordian-90` 跟踪；有限测试不证明无限时长或所有应用行为。

完整依赖扫描 JSON、复现输出和全量测试日志保留在本机审核证据目录，未把用户配置、录音或令牌上传到 GitHub。
