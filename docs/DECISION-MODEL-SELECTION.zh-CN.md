# Recordian 上下文纠词模型选型：Decider 4B v2

测量日期：2026-09-25。目标设备为 192.168.5.111 的 Ryzen AI MAX+ 395 / Radeon 8060S（gfx1151）。

**选择 Decider 4B v2 作为本地纠词模型；用户已于 2026-09-25 授权切换。** 在本次中文夹英文、jeff/jev 上下文判断样例中，它的稳态新句延迟低于 SemIf 和 Winnow，人名等负例的误改更少；热词纠正数量略低于 SemIf。这是速度与误改风险的取舍，不能解释为所有听写内容的准确率都更高。

这个模型负责判断已有纠词候选是否适合上下文。音频识别继续使用 Confucius；中文数字、端口、网址中的“点”等继续经过本机确定性格式化。决策模型本身不生成任意改写，也不能单独发现所有错别字。

## 为什么没有按榜单总分直接选择

查询的是 [Jev Decision Index](https://huggingface.co/spaces/multimodalart/jev-decision-index)，数据快照时间为 2026-09-24T18:19:21Z。其开放模型测量使用 NVIDIA RTX PRO 6000，和本机 AMD 的实际耗时不能直接互换；Decision Index 也不是百分比准确率。

| 候选 | 榜单 Decision Index | 本次处理 |
| --- | ---: | --- |
| CLM | 6.51 | 撤回优先部署计划 |
| 现有 SemIf | 25.70 | 保留为实测基线 |
| Decider 4B | 36.58 | 部署并测试当前 v2 固定版本 |
| Winnow 12B Q8 | 45.05 | 部署作为更大模型的对照 |
| 官方 Jev | 51.67 | 云端参考；本轮未对官方服务做同语料实测 |

榜单中 Decider 条目的 checkpoint revision 未注明，因此不能把榜单分数说成这次固定 v2 权重的已验证分数。选型依据以同一台 111 上的实测为主。Winnow 的榜单总分更高，但本机延迟约为 Decider 的 2.5 倍，在这套纠词语料中的正确纠正数量只多 2 条。

## 同机测量结果

使用 `server/decision_trial/cases.json` 的 99 条主句及 99 条不同改写句，共 198 个唯一请求。每个模型还跑了 99 条完全重复请求，这轮仅观察重复效应，不参加下表的准确性合计。三者收到的主句、改写句完整请求分别逐字节一致，使用各自发布配置的温度，不把跨模型概率当作同样校准的置信度。

| 模型 | 新句延迟中位数 | 新句延迟 P95 | 应纠热词正确接受 | 不应改写的负例被误改 | 原始语义类别答对 |
| --- | ---: | ---: | ---: | ---: | ---: |
| SemIf Qwen3.5-4B Q8 | 150.988 ms | 165.521 ms | 69/92 | 9/90 | 119/192 |
| Winnow 12B Q8 | 304.969 ms | 323.094 ms | 70/92 | 5/90 | 124/192 |
| **Decider 4B v2 BF16** | **120.462 ms** | **124.228 ms** | **68/92** | **2/90** | **152/192** |

- 延迟取服务已热的 99 条新改写句；正确接受、误改与语义类别合并主句和改写句。它们的分母不同，不能相加。
- 每组 54 条 tool 样例中，产品结构保护会跳过 8 条，只对余下 46 条评价热词是否被接受。否定、元话语、重复别名等受保护情况单列，不能伪装成模型答对。
- 每组 45 条负例均计入误改分母，其中只有 14 或 15 条会经过结构保护进入模型判定；表中的误改是“结构保护加概率门槛重放”的输出。
- 原始语义准确率排除每组 3 条同小句多目标、无法明确标定指向的样例，故为 192 条。类别为 tool / person / unclear，这不是语音转文字的准确率。
- 固定门槛为最大概率至少 0.70、与第二名差至少 0.20。弱分布拒绝、错误响应、结构保护跳过分别计数；拒绝改写不等于语义判断正确。
- 三个模型各 297 次真实 HTTP 请求均无错误、超时或坏分布；本次会进入产品判定的请求均在 350 ms 内。HTTP 捕获超时为 3 秒，350 ms 是统计预算，本基准没有执行完整产品异步截止时间。

保守性的代价在新句轮更明显：Decider 正确接受 32/46，SemIf 和 Winnow 均为 35/46。Decider 也仍会误改“我打算找 Jeff 确认一下”这一人名语境。不能靠降低门槛来美化这套语料的命中率，门槛调整需要另外保留的测试集和真实使用证据。

## 部署与冷启动

| 项目 | Decider 试用配置 |
| --- | --- |
| 接口 | `http://192.168.5.111:42071/v1/systemone` |
| 容器 | `recordian-decider-trial` |
| 代码版本 | `5f91c011f05fa4b685f0845281a0805a56eb0169` |
| 权重版本 | `49564ddcfccafb6db563eb757c1d41e6c78dcb56` |
| 权重 | BF16，8,411,558,400 字节 |
| 权重 SHA256 | `69e6895461c425c6469cd304838a2e5673141613c2da04782026e37c1481d936` |
| 温度 | 1.935 |
| 执行方式 | ROCm PyTorch + FLA，eager；关闭 torch.compile、FP8、CUDA graphs |
| 资源限制 | 18 GiB 容器内存、4 CPU；仅绑定 111 的局域网地址 |

首次真实推理耗时 **53,089.933 ms**，第二条不同中文句子为 118.817 ms。前者包含首次加载及内核准备，不能从用户体验中省略；上表所有 Decider 测量都发生在该初始化之后。首次推理必须在服务就绪前完成，具体启动预热、校验及回滚以 [Decider 部署说明](../server/decider_trial/README.md) 为准。

本轮已加启动预热并实际重启验证：官方模型加载后，先经过两次真实中文 choice，再开放 HTTP 就绪；本次重启 T+3/T+5 秒仍未就绪，T+7 秒健康检查首次返回 200。持久化内核缓存下，两次内部预热合计约 1 秒，之后两条新句分别 116.923 / 116.461 ms。故意让第二次预热请求失败时，容器退出码为 3，29 秒观测内健康检查从未返回 200。新启动还会重新验证完整权重 SHA256，这次校验耗时 3.668 秒。

测量时按隔离试用运行（`restart=no`）。用户授权采用后，已将现有 `recordian-decider-trial` 容器的重启策略改为 `unless-stopped`，以便随 Docker 恢复运行；修改策略没有重启容器，原有启动预热、权重和资源限制继续使用。这里记录的是策略配置及容器运行状态，尚未通过重启整台服务器验证自动恢复。Winnow 对照服务及其构建容器在测量完成后已停止，权重和复现资料保留；Decider 和原有 SemIf 保留运行。部署脚本仍以隔离试用为默认方式，重建容器时需要重新设置采用后的重启策略。

AMD 部署是本项目实测的试用适配，不代表上游已经官方支持这套硬件。模型与接口依据 [Decider 模型页](https://huggingface.co/Mapika/decider-4b) 和 [官方实现](https://github.com/Mapika/decider)；Winnow 依据 [模型页](https://huggingface.co/EldanRing/Winnow-12B) 和 [官方实现](https://github.com/EldanRing/winnow-inference)。

## 实际流式纠词调用

`integration_probe.py` 使用产品 `corrector_from_args` 工厂，真实执行 submit / poll / finish，并调用 111 的 Decider。配置仅在探针进程内指定，没有修改用户设置、打开麦克风或向应用输入文字。修复探针的后台日志观测竞态后，结果为 **5 项中 4 项通过，1 项语义错误**：

| 场景 | 实际结果 |
| --- | --- |
| `今天下午先把jeff安装好` | 最终为 `今天下午先把jev安装好`，122.829 ms |
| `Jeff帮我调试脚本` | 人名保护保留原文，未请求模型 |
| `端口一百零二，访问https://example点com/path` | 本机规范化为 `端口102，访问https://example.com/path` |
| 人为将请求预算压到 50 ms | 捕获 ReadTimeout，finish 在 54.283 ms 返回原文；之后的日志观测等待另计 |
| 前文含软件安装，本句 `我打算找 Jeff 确认一下。` | 错误输出 `我打算找 jev 确认一下。`，135.150 ms |

最后一项已登记为 `Recordian-5fn`，不能用另外四项通过掩盖。用户在获知这一限制后授权切换模型；本次采用不代表该误改已修复。当前人名指向与历史工具语境的优先级，以及正常热词召回，仍需继续验证。原有实际桌面、微信和用户声音验证继续由 `Recordian-91k`、`Recordian-cie` 跟踪。

## 采用后的本机配置

切换任务为 `Recordian-dnm`。本机 `~/.config/recordian/hotkey.json` 仅修改 `semif_endpoint`，从 `http://192.168.5.111:42032/v1/systemone` 改为 `http://192.168.5.111:42071/v1/systemone`。`correction_provider="semif"` 是现有 SystemOne 兼容适配器的内部标识，继续使用这个标识；实际模型以 HTTP 响应的 `model="decider-4b-v2"` 为准。等待预算保持 `semif_timeout_s=0.35`，已有热词、Confucius ASR 和流式配置不变。

原配置已备份为 `~/.config/recordian/backups/hotkey.json.bak-decider-switch-20260924T213241Z`，备份和当前配置权限均为 `0600`。备份 SHA256 为 `e2a7968a652a08cb7bd3f906e41215fc5b302859750184fe731e1661266dc4df`，切换后为 `d8d63cde815a3acd06d83ec8dddfbd481c58f983702f16f575126101cc9e05bc`；所有非端点字段逐项相等。听写后端只在启动时读取配置，生效验收需同时核对重新启动的后端、来自该配置的产品工厂解析结果及真实 HTTP 模型返回；只修改文件或在探针中覆盖端点不足以证明生效。

本次在确认后端没有录音子进程和录音临时目录后重新加载：旧后端 PID `390811` 已退出，原托盘 PID `390720` 拉起新后端 PID `449590`，2026-09-25 05:37:59（北京时间）记录 `backend_ready`，复核时仅存在一个后端。新的后端命令行使用上述配置路径，进程启动时间晚于配置写入。由真实配置解析器及 `corrector_from_args` 创建的纠词器调用 42071，HTTP 200 返回 `decider-4b-v2`，`打开jeff工具检查这个项目` 输出为 `打开jev工具检查这个项目`；该次 HTTP 往返 121.9 ms，产品 `finish` 225.3 ms，低于保留的 350 ms 预算。该记录验证了重载和按当前配置的产品调用，不是读取后台进程内存，也不是向真实输入框听写的测量。

重载时另发现既有进程清理逻辑仅以整条命令行的子串识别后端，可能把含代码说明的任务命令误当作后端。观察命令退出 143，工具修订任务亦未交付最终报告；当时日志记录清理了两个匹配进程，但没有记录被清理的 PID，因此具体退出因果仍待验证。此问题登记为 `Recordian-cyx`，本次没有修改清理逻辑。后续采用重载后的独立观测确认了唯一后端及就绪状态；不能把中断的工具修订任务算作验证通过。

切换证据单独保存在 `Recordian-control/.runs/20260925-decider-switch/reports/`，不覆盖本轮模型比较的历史测量。恢复时将 `semif_endpoint` 改回 42032，并在没有录音或待处理输入时重新加载听写后端；若切换后又调整了其他设置，应仅回改端点，以免用旧备份覆盖后来的设置。

DSH 最后复核了 4 个既有格式化用例（基数、带端口等标记的完整数字、网址点号及受保护文本），全部通过；唯一警告是沙箱不能写 pytest 缓存。它再次执行真实配置的产品纠词探针，HTTP 119.7 ms、`finish` 255.6 ms，模型返回与纠正文本均符合上述结果。[采用验收摘要](../server/decision_trial/results/2026-09-25-activation.json) 保存这次调用、进程重载、配置及原始证据文件的 SHA256。

## 证据和使用边界

- [测量摘要及原报告 SHA256](../server/decision_trial/results/2026-09-25-summary.json) 保留逐轮指标、温度及合并计数；[基准说明](../server/decision_trial/README.md) 提供运行和离线重算方法。
- 原始完整请求、响应概率、HTTP 时间记录位于本次运行目录的 `reports/semif-baseline-final.json`、`reports/winnow-benchmark-final.json`、`reports/decider-benchmark-final.json`。SemIf/Winnow 的指标修正使用原 HTTP 记录离线重算，没有重复测量耗时。
- 部署、测试脚本及独立审查由 Grok 4.7 和 DeepSeek DSH CLI 执行，协调者复核实际记录、指标和最终文件。
- 本基准覆盖合成中文文本及单并发请求，未覆盖真实录音、浏览器/微信/编辑器输入法通道、长时间负载、多客户端争用或服务器重启后的日常自动恢复。流式代码探针和本机配置切换均应与真实麦克风和 IME 验收区分。
- 现有 SemIf 服务保留在 42032，便于对照和回滚。本机采用记录见上节；模型选型、配置生效和完整输入法体验属于不同的验证范围。
