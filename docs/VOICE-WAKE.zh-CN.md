# 语音唤醒：本机配置与验证

2026-09-27：本机已启用 CPU 上的 Sherpa ONNX 中文 INT8 唤醒模型。说“嗨小二”或“嘿小二”，等录音球出现再说正文。按键录音继续可用；语音唤醒后的录音仍走原来的 Confucius GGUF Q4 流式识别，用途由 Agent 设置决定；F9 始终普通输入。

## 依赖与启动

在桌面程序使用的虚拟环境中安装 `.[wake]`。本机验证的版本为 Python 3.14、sherpa-onnx/core 1.13.8、webrtcvad-wheels 2.0.14、sentencepiece 0.2.2。WebRTC VAD 在本机从源码构建成功。Sherpa 的中文 text2token 也会导入 sentencepiece，因此它现在属于 wake 可选依赖。

唤醒随 Recordian 桌面服务启动；大语音识别模型继续由原有常驻服务管理。只有麦克风成功打开，才记录 `voice_wake_ready`。启动失败要检查 `voice_wake_setup_failed`、`voice_wake_init_failed` 或 `voice_wake_runtime_error`，不能仅凭配置开关判断已可用。

## 本机使用的设置

以下是已部署的设置说明，不更改所有用户的默认值：

| 项目 | 值 | 用途 |
|---|---|---|
| 启用 | `enable_voice_wake=true` | 随桌面程序监听 |
| 唤醒词 | 前缀“嗨、嘿”＋名字“小二” | 保留原来的称呼 |
| 裸名字触发 | `wake_allow_name_only=false` | 日常提到“小二”不作为完整唤醒指令 |
| 前缀额外变体 | `wake_auto_prefix_variants=false` | 减少重复、宽泛的关键词条目 |
| 声调变体 | 保留开启 | 保留原有发音容错 |
| 语音检测 | 20 ms，连续 2 帧 | 按真实音频帧计数，进入门槛为 40 ms 语音；这不是完整唤醒延迟 |
| 前置音频缓存 | 500 ms | 避免语音门控裁掉唤醒词开头，仅用于唤醒模型 |
| 唤醒词末尾保留 | 600 ms | 给模型留出尾音和解码上下文 |
| 重复触发冷却 | 3 s | 冷却期间丢弃音频 |
| 唤醒后未说话等待 | 4 s | 给用户准备正文的时间 |
| 正文停顿结束 | 基础 1 s，声纹额外等待 0 s | 缩短停说后的等待；不包含 ASR 最终收尾或 Agent 执行时间 |
| 正文语音检测强度 | 2 | 比原来的 3 稍宽松 |
| 主人验证 | 保留已有样本、阈值和配置 | 本轮未重新录制声纹或宣称完成阈值校准 |

主人的既有验证是频谱特征相似度判断，不应作为身份认证。当前阈值沿用原值；测试不足以证明对其他说话人的长期拒绝率。

## 代码修复

- 每次读取一个 10/20/30 ms 的语音检测帧，修复原来把 100 ms 音频块计作一帧的问题。
- 录音和处理期间继续排空麦克风，但跳过唤醒解码；恢复时不复用上一段音频。
- 麦克风溢出、暂停或语音门控关闭时新建解码流，丢弃编码器旧特征。仅重置关键词搜索不能清空这些特征。
- 声纹音频缓存按帧长度保留完整且有限的时间窗口，兼容 10 ms 帧超过 100 块的情况。
- 麦克风打开后才报告就绪，收到停止请求后不再处理刚读入的数据。

## 停说结束的后续调整

按用户反馈将本机静音等待从 2 秒改为 1 秒，主人额外等待从 0.4 秒改为 0。代码原先把短配置强制抬到 1.5 秒，现在允许最低 0.5 秒。弱能量保活只允许在最近一次 VAD 语音后的 0.3 秒内延长，避免持续弱噪声无限刷新最后说话时间。更短的停顿设置可能让长时间思考被视为一句结束；F9 松开结束的行为不受影响。首次加载此代码需要重启桌面进程；不得打断正在执行的 Agent 任务。

回归用受控音频帧和时钟模拟真实语音结束后的持续弱噪声，确认最终只自动停止一次，且不会等完整个噪声流。未用用户当前麦克风执行额外任务。

## 验证与边界

- 自动化测试覆盖真实唤醒循环中的帧门控、静音、录音期间暂停、冷却、溢出、声纹窗口、就绪状态，以及唤醒与按键录音的状态连接。全部使用替代音频流，不向用户应用输入内容。
- 使用本地真实 INT8 模型回放官方测试音频，4 个对应中文关键词样例均触发；普通中英文公共音频约 37 秒未触发本机唤醒词。这是小样本检查，不是长期误唤醒率评估。
- 12 秒真实默认麦克风检查通过启动、连续读取和正常退出；稳定监听时采样 CPU 约为单核 3%～4%，该独立检查进程峰值内存约 146 MiB（包含 Python、依赖和模型）。使用 CPU provider，不额外加载 GPU 唤醒模型。
- 本机原来的主人样本仅在本地回放检查，无音频上传。没有包含“嗨小二／嘿小二”的标注用户录音，因此本轮没有宣称完成该说话人的唤醒率或声纹阈值标定。
- 正文录音仍在唤醒后启动：先等录音球，再说正文；不保证把与唤醒词紧连且无停顿的正文开头补回。
- 验证使用后台音频回放和替代回调；没有操作前台鼠标或键盘，也没有把这些检查表述为 Jev GUI 验收。

官方参考：[关键词识别说明](https://k2-fsa.github.io/sherpa/onnx/kws/index.html)、[预训练模型与测试方法](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html)。
